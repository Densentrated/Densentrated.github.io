VEX

Problem

Reviewing notes takes a lot of time, especially when they aren't perfectly organized. Tracking down a specific formula or the right code pattern means digging through pages of content manually — a slow, frustrating process.

Solution

LLMs make for a great natural language interface for information© Untitled. retrieval, so the goal was simple: narrow one down to just my notes. Since my notes are already synced to the cloud via Obsidian Git, pulling the latest version was straightforward. The harder problem was figuring out which notes to actually send to the model — sending everything wasn't an option.

A vector database turned out to be the right tool for the job. The pipeline works like this: a query goes into the vector database, the top n most relevant chunks are retrieved, and those chunks along with the original query are passed to the LLM with a system prompt tuned for knowledge retrieval. The result is fast, context-aware answers pulled directly from my own notes.

On the infrastructure side, I built a lightweight web server using Gin Gonic to automatically pull the latest notes whenever I push to the repo. The vector database and its interface live inside the notes repo itself, keeping everything self-contained. A simple frontend rendered at the /portal endpoint ties it all together into a usable web portal.

Results

I now had a web portal I could use to query my notes. You can check the GitHub page for the project here: https://github.com/Densentrated/v_e_x_

Credits

Built independently. The chromemgo package was especially useful — it runs the vector database in-process, eliminating the need to manage it as a separate service.
